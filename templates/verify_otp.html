Key facts this template is built around: - GET is only reachable with session["signup_email"] set (the view redirects to signup otherwise) -- {{ email }} here is always a real server-provided value, never client state. - POST /verify-otp/ reads request.POST (form-encoded), NOT a JSON body -- request.POST.get("otp") would be empty against a JSON fetch body, so this page submits as multipart/form-data (FormData), same as the page it replaces. DS.api (JSON-only) is deliberately NOT used for this call; DS.api.getCsrfToken() is reused for the token itself, which is the actual duplicated logic Phase 2 flagged. - POST /verify-otp/ ALWAYS returns HTTP 200 with {"status": "success"} or {"status": "error", "message": "..."} -- branch on the JSON body, never on response.ok/status. - Exact backend messages (verbatim, not paraphrased client-side): "Session expired" | "Signup session expired. Please sign up again." | "Verification code is required." | "Verification code not found or already used. Please request a new one." | "Verification code has expired. Please request a new one." | "Too many incorrect attempts. Please request a new code." | "Invalid verification code." - The two "expired signup session" messages mean the backend has already deleted PendingSignup/EmailOTP server-side -- no further verify attempt on this page can ever succeed, so the UI routes the user back to signup after showing the message, instead of leaving a dead form on screen. - POST /resend-otp/ takes no body fields (session only) and returns one of: 400 {"error":"Session expired"} | 400 {"error":"Signup session expired. Please sign up again."} | 429 {"error":"Too many requests. Please try again later."} (IP throttle) | 429 {"error":"Please wait a moment before requesting another code."} (30s cooldown) | 429 {"error":"Too many codes requested. Please try again later."} (5/hour window) | a structured email-failure body via email_error_response() | 200 {"status":"success"}. DS.api IS used here (no request body needed, and DS.api.ApiError/extractErrorMessage already normalizes both the plain-string and structured error shapes -- this is exactly the "6 independent CSRF-token readers" duplication Phase 2's api.js was built to replace). - OTP is always exactly 6 digits (otp_utils.OTP_LENGTH), expires 5 minutes after issue, allows 5 wrong attempts, resend cooldown is 30s with a 5-per-60-minutes cap -- all server-enforced. Every timer/counter below is UX-only and never blocks or replaces a real request; the server's own error response is what actually governs whether a request succeeds.
