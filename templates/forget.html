Confirmed unchanged from the contract doc; key facts this template is built around: - All four endpoints are POST-only, form-encoded (request.POST), return JSON, and are read via `request.session` (reset_email / otp_verified) rather than any client-supplied token. CSRF via {% csrf_token %} value read through DS.api.getCsrfToken() (the shared reader -- the old page had its own getCSRF() duplicate, one of the 6 Phase 2 flagged). - ENUMERATION RESISTANCE IS LOAD-BEARING: forgot_send_otp and forgot_resend_otp return the identical generic body ({"status":"otp_sent"/"otp_resent", "message":"If an account exists for this email, a reset code has been sent."}) whether the email exists, doesn't exist, or was silently cooldown/window throttled. This page NEVER inspects or branches on which of those three actually happened -- it shows the literal server message and nothing else, on every non-error outcome of those two calls. IP-throttle (429) and "Session expired" (400) are the only responses that are genuinely distinguishable, and neither reveals account existence either. - forgot_verify_otp (unlike signup's verify_otp) DOES propagate a real HTTP status (400/403) with {"error": "..."} -- messages are the same otp_service strings as verify_otp.html: "...required.", "...not found or already used...", "...has expired...", "Too many incorrect attempts...", "Invalid verification code." - forgot_reset_password requires session["otp_verified"] (403 "OTP not verified" otherwise -- not reachable through normal use of this page, since it only shows the password stage after a real "verified" response). On success it calls request.session.flush() -- this DESTROYS the session outright. There is no auto-login. The only correct next step is sending the user to the real login page, never assuming an authenticated state. - Password policy is the same real Django validators as signup (MinimumLengthValidator/8, NumericPasswordValidator, CommonPasswordValidator; UserAttributeSimilarityValidator is configured but validate_password() is called with no user here either, so it's inert) -- same hint text as signup.html, not a different or stronger claim. - Resend cooldown/window use the exact same global constants as signup (30s cooldown, 5/60min window) -- rate_limit.py's constants aren't purpose-specific, only the cache keys are.
